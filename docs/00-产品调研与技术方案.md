## 一、市场调研结论

### 1.1 赛道信号（2026-09 检索实证）

1. 个人 AI 助理竞争维度已从"回答质量"转向**主动性、持久记忆、跨应用行动**（Vellum / Mastra 2026 评测）；
2. 行业共识：**Agent ≠ 自动驾驶**——Manus 2026 评测结论"impressively autonomous, but not an autopilot"，关键决策须留人工监督（验证 HITL 设计）；
3. 个人记忆类明星产品 Rewind/Limitless 被 Meta 收购后于 2025-12 停服——**数据主权成为真实痛点**；
4. 学习域 AI 集中在"笔记转闪卡 + 间隔重复"单点（Anki+AI / RemNote / TikoNote），无闭环管理。

### 1.2 无偏评测修正（子 Agent 冷启动评测，关键结论）

- **致命伤**：①自动化了用户不缺的（计划拆解是 commodity），旁观了真正缺的（执行拉力、崩盘重启）②自托管四道墙挡住目标用户 ③周报输入数据太薄必产车轱辘话；用户最可能死于 **Day 7 首份周报后的 48 小时**；
- **已采纳的修正**：计划从"AI 生成"改**"导入对齐"**（贴入参考计划，AI 负责排程与调整）；打卡加**卡因标签**（分心/太难/疲劳/被打断）；开发者托管实例 + docker-compose 降级为极客选项；砍前端多 Agent 展示；公开自用数据作作品集护城河；目标用户收窄为**懂技术的自学者**；
- **残留风险**（如实记录）：不惩罚 + 无游戏化的留存钩子只解决一半，靠试运行数据验证。

### 1.3 手机端基准（Must-have）

打卡路径 ≤2 步 / 提醒必达 / 数据服务端持久 / 打卡日历+streak+完成率图表 / 深色模式 / 离线可打卡 / 微信内可用。PWA 短板缓解：manifest shortcuts、pinned shortcut、Badge API、Bark/PushPlus/企微推送通道（Server酱 5 条/天仅兜底）。

## 二、产品定位

**一句话**：面向懂技术的自学者的成长执行系统——贴入备考/求职/健身计划，AI 排进每天并盯着执行，每周给"它懂我"级复盘洞察与调整提案（审批生效），自托管 + BYOK，数据在自己手里。

**适用条件**：周期 2 周~12 月、有明确目标/截止、需持续执行、可复盘。**不适用**：纯记录（记账）、即时满足、无目标漫生活。

**边界原则**：只管"执行与坚持"，不生产"内容与教学"（不做动作库/课程/饮食记录）。

**三条产品理念**：①不制造焦虑（断签只归因不惩罚）②少即是多（每日核心 ≤3）③数据自主（导出/自托管）。

| 场景 | 目标示例 | 计划来源 |
|---|---|---|

## 四、功能清单（开发对账单）

### 手机端（三 Tab）

- **今日**：晨间摘要卡（7:00 模板生成零 LLM）/ 今日任务（≤3，一键打卡）/ 跳过+卡因四选一 / 自报时长（可选）/ 生活三打卡（睡眠/运动/心情）/ 今日进展卡 / 周三小结卡 / 桌面快捷入口（shortcuts+钉屏+角标）
- **对话**：与总编对话（路由教练/复盘师，拒闲聊）/ 计划导入对齐入口 / 补救方案 / 调整审批卡（简版）/ 晚间轻复盘（21:30，两问，1 分钟）
- **档案**：打卡日历热力图 / streak（无惩罚）/ 完成率趋势 / **卡因分析** / 里程碑进度（含 P2 指标型：体重/配速/词汇量曲线）/ 周报历史 / 导出 CSV·MD

### 电脑端

计划对齐工作台（贴文本→预览→diff 高亮审批）/ 完整周报图表 / 数据管理导出。

### 设置

BYOK 三件套（base_url + key + model，OpenAI 兼容，Fernet 加密落库）/ 推送通道（带测试按钮）/ 提醒时间 / 任务上限 / 深色模式。

### 系统级

双通道推送（站内 + Bark/PushPlus/企微）/ 离线打卡本地暂存自动补传 / 微信内 UA 检测引导浏览器打开 / 登录鉴权 / **计划兜底**（LLM 故障退化为模板排程，永不白屏）。

### 明确不做

番茄钟、游戏化积分惩罚、社交督学、原生 App（现阶段）、陪聊、财务记账。

### 埋点（Day1 起，作品集护城河）

打卡率曲线、卡因分布、提案采纳率、周留存——定期公开到 README。

## 五、Agent 架构

### 5.1 判定标准

Agent = ①自主工具循环（模型根据上一步结果决定下一步调什么）②主动性（没人提问也干活）③记忆+中断（跨天状态、HITL 暂停恢复）。三缺一即伪 Agent。

### 5.2 拓扑：LLM Agent × 3 + 确定性管家

- **总编**：意图路由与会话（LangGraph Supervisor）
- **教练**：`parse_plan_text` / `get_goal` / `get_available_hours` / `propose_schedule`（确定性排程算法）/ `create_milestones` / `submit_proposal`（触发 interrupt）/ `revise_proposal` / `detect_conflicts`(P2)
- **复盘师**：`get_completion_stats` / `get_skip_reasons`（卡因钻取）/ `get_time_patterns` / `get_streak` / `get_trend` / `generate_report` / `propose_adjustment`
- **管家（非 Agent）**：晨推渲染、推送分发、离线同步——定时任务 + 模板，零 LLM
- 共用：`send_push` / `query_today` / `query_week` / `export_csv`

排程算法是写死的代码，LLM 只决定何时调用与如何解释结果。

### 5.3 写权限矩阵（信任基石）

| 数据 | 权限 |
|---|---|
| 查询（读） | 自由 |
| 事实记录（用户口述） | 直写 |
| 计划类（Agent 决策产物） | 起草 → HITL 审批 → 落库（版本化可回滚） |
| 历史事实（打卡/卡因） | **永不可写** |
| 账号与 BYOK 密钥 | 不可写 |

自治等级旋钮：L1 提案制（默认）/ L2 白名单免批（单任务顺延等小改动，可开）/ L0 只读顾问（可降）。

**原则：Agent 可以修改未来的安排，但不能篡改过去的事实。**

### 5.4 图表与表格

聊天内 Markdown 表原生支持；图表 = Agent 出"数据+配置(JSON)"，前端 ECharts 渲染（固定图表零 token，对话内临时图表随口点单）。不生成静态图片。

## 六、技术栈（已按本机环境实证）

Python 3.12（独立 conda 环境 growthcrew）/ FastAPI / LangGraph（Supervisor+interrupt）/ langgraph-checkpoint-postgresql / FastMCP（P1 装）/ SQLAlchemy 2.0 + Alembic / PostgreSQL 16 / APScheduler / argon2id + JWT（旋转 refresh）/ cryptography(Fernet) / httpx / pytest+pytest-asyncio（≥80%）/ ruff + mypy strict / pip-audit / Next.js(App Router)+TS+Tailwind+shadcn/ui / ECharts / Serwist(PWA) / Caddy / GitHub Actions / AGPL-3.0。

LLM 接入：openai SDK 动态 base_url（BYOK），不引 litellm；轻任务用 Flash 级模型。成本目标：每周 <20 次 LLM 调用，¥1~2/月/人。

## 七、仓库结构与分层铁律

```
backend/app/{api/v1, services, repositories, models, schemas, agents, tools, core, jobs}
frontend/  deploy/  docs/(adr)  .github/workflows/ci.yml
```

**铁律**：api → service → repository 单向依赖；业务规则只在 service；SQL 只在 repository；**Agent 工具只调 service**（与前端同一条被测试覆盖的写入路径）。

## 八、安全设计（红线 + 11 项）

**红线（CI 检查，违反即挡）**：源码/配置/测试/文档中禁止任何真实密钥、密码、token 字面量；一律 .env（gitignored）+ 环境变量注入。

密钥管理（BYOK Fernet 加密落库，主密钥仅环境变量）/ argon2id + 登录限速 + 模糊错误提示 / 短 access + 旋转 refresh / Caddy 自动 HTTPS+HSTS / SQLAlchemy 参数化 + Pydantic 全边界 / **Prompt 注入防御**（贴入文本当数据、工具权限矩阵、LLM 输出过 schema 才落库）/ 写入事务+版本化+审计 / pip-audit+lock+Dependabot / 容器非 root 只读 / 每日加密备份异地 30 天 / DB 最小权限账号。

## 九、开发流程

**每功能循环**：设计小节确认 → 实现+测试 → ruff/mypy 自检 → 全量测试 → 暂存（git add）→ 用户 commit+push → 部署 → 验证报告。

**CI 四关**：ruff lint / ruff format / mypy strict / pytest(≥80%)，外加 pip-audit（试运行一月后强制）。

**DoD**：代码+测试绿+自审清单+CI 四关+部署验证+文档更新，六项缺一不算完。

**提交规范**：Conventional Commits；trunk-based（main 永远可部署，feat/xxx 分支）。

## 十、路线图与验收门禁

| 阶段 | 内容 | 可行性门 | 意义门 |
|---|---|---|---|
| P0 | 仓库/环境/认证/部署链路 | 云端 URL 可打开、接口全绿 | — |
| P1 | 导入对齐→审批→打卡→晨推→晚间复盘 | 教练 20 次生成 schema 校验全过 | 连续真实用 3 天 |
| P2 | 周报洞察/周三小结/补救方案/图表/双通道推送/离线 | 7 天定时零漏发 | 完整周循环 + ≥1 条自己没意识到的洞察 |
| P3 | 兜底/备份/导出/弱网加固 + 试运行 | 断网可补传、模型故障不阻塞 | 连续 2 周日常使用、成本 ≤ 预算 |
| P4 | 错题本（无 RAG：题目即上下文） | 讲解准确率抽检 | 真的回头复习 |
| P5 | 专业问答+知识库 RAG | 先专项调研（切块/混合检索/溯源/评测） | 届时定 |

**迁移预留**（零成本纪律）：业务逻辑零前端 / TS 类型从 OpenAPI 生成（orval）/ 推送通道适配器模式 / 核心不绑死 service worker。迁移触发：用户要小组件 / 推送拖留存 / 商店分发需求。
