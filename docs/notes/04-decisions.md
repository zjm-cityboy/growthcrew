# 04 · 架构决策四则（ADR = 面试故事）

> 每则按"问题 → 选项 → 拍板 → 面试一句话"。完整版在 `docs/adr/`。
> 面试官问"你做过什么技术决策"时，四则任挑一则展开 90 秒。

## 决策一：手机优先 PWA，不做原生 App（ADR-0001）

- **问题**：核心场景在手机，但 solo 开发做原生（新工具链/商店审核/软著）偏离 Agent 主线；
- **选项**：PWA（零新增技术栈）/ Expo / uni-app；
- **拍板**：PWA + 微信通道推送（Bark/PushPlus/企微免费档）；调研实证桌面小组件是留存第一杠杆而 PWA 做不了 → **迁移路径写死**：后端 API-first（业务逻辑 100% 服务端、TS 类型可从 OpenAPI 生成），将来 Expo 重写 UI 壳约 1-2 周、后端不动；
- **面试一句话**："我用 PWA 先验证产品假设，同时用 API-first 架构保证原生迁移只换壳——还把触发迁移的条件（用户要小组件/推送拖留存）定义成了可观测的数据指标。"

## 决策二：只在"见机行事"处用 Agent（ADR-0002）

- **问题**：最初设想 4 个 LLM Agent；无偏评测指出"把确定性工作包装成 Agent 只增加成本延迟与故障面"；
- **拍板**：LLM Agent ×3（总编路由/教练规划/复盘师 P2），管家（晨推/打卡/统计）= 定时任务+模板**零 LLM**；前端砍掉多 Agent 展示 Tab；
- **面试一句话**："判断一个环节要不要 Agent 的标准是——下一步是否依赖上一步的结果临场决定。晨间摘要是固定查询+模板，写死；教练看到排程超载要不要下调重排，这才是 Agent。"（这句是被外部评测挑战后迭代的，可以大方讲。）

## 决策三：HITL 审批放服务层，不用 interrupt（ADR-0003）

- **问题**：harness 用 LangGraph `__interrupt__` 挂起等人批；这里照搬需要跨请求保存图状态，而图节点闭包持有请求 A 的 DB 会话，请求 B 恢复时会话已关；
- **拍板**：Agent 编排在**单次 HTTP 请求内**跑完（图+工具循环），审批暂停落在 `plan_proposals` 表——approve/reject 是服务层确定性操作（条件 UPDATE 原子防并发双批），重启天然免疫（pending 提案永远可批）；
- **面试一句话**："我论证过为什么不用 interrupt：跨请求会话共享的复杂度不成比例，而提案表本身就是持久审计。interrupt 留给 P2 的多轮对话场景——知道什么时候不用一个技术和会用它同样重要。"

## 决策四：token 存 localStorage 的显式取舍（ADR-0004）

- **问题**：JWT 放哪？localStorage 有 XSS 面，httpOnly cookie 要后端 CSRF 改造；
- **拍板**：当前自托管+无第三方脚本 → localStorage；**迁移触发条件写进 ADR**：引入第三方 JS / 开放公网注册 / 出现 XSS 修复记录，任一发生即迁 cookie+CSRF；
- **面试一句话**："这不是永久决定，是带触发条件的分期决策——债务显式写在 ADR 里，比假装没有债务诚实。"

## 附：两个产品级决策（面试聊产品用）

- **计划从"AI 生成"改"导入对齐"**：无偏评测指出考研计划是 commodity（名师课表遍地），AI 生成的计划不会更好；改为贴入参考计划、AI 负责排程与调整——承认 AI 不如名师，AI 才站到它擅长的位置；
- **不制造焦虑的量化落地**：断签不惩罚只归因；每日核心 ≤3 件写进排程算法上限；昨日 0 完成时晨推不报数字（有测试锁定该文案分支）。
