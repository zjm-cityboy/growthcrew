# 02 · 安全设计精讲

> 比喻主线：这套安全设计 = 一栋小楼的门禁系统：前门（认证）、保险柜（BYOK 加密）、访客限流（rate limit）、防社工（注入与枚举）。

## 一、认证链路全景（谁是谁）

```
注册 → 密码只存 argon2id 哈希（库被拖也还原不出明文）
登录 → 发一对令牌：access（15 分钟）+ refresh（30 天）
访问 → 请求带 access；过期 → 前端用 refresh 换新对（旋转：旧 refresh 立即作废）
```

- **为什么 argon2id 不是 bcrypt**：argon2 是 2015 密码哈希竞赛冠军，抗 GPU/ASIC 暴破（内存难题），参数默认即 id 变体；bcrypt 不是不好，是更新一代的问题。
- **refresh 为什么要旋转**：泄漏可检测——旧 refresh 被 reuse 时说明有第二个人在用；实现要点：库里只存 SHA-256 摘要（拖库也造不出可用令牌）+ **原子撤销**（`UPDATE ... WHERE revoked=false` 抢占，并发重放必有一个失败，这是第二轮审查抓出来的竞态）。
- **账号枚举防御**：用户不存在时也跑一次 dummy argon2 校验抹平时延，"用户名或密码错误"统一模糊提示。

## 二、BYOK 三层保险柜（用户的大模型密钥）

```
明文 key ──只在──> 内存（构建 LLM 客户端时解密）
落库     ──Fernet 加密──> api_key_encrypted 列
出库展示 ──永远脱敏──> "sk-***abcd" / "已配置（隐藏）"
```

- **Fernet 是什么**：对称加密（AES-128-CBC + HMAC 签名），一把主密钥加密所有用户的 key；密文自带完整性校验，被篡改会解密失败；
- **主密钥分级**：`GC_ENCRYPTION_KEY`（环境变量，独立于 JWT 密钥）→ prod 未配置启动即失败；dev 不配则进程内临时密钥（重启失效，逼你本地养成显式配置习惯）；
- **密钥轮换**：换了主密钥，旧密文解不开 → `CryptoError` 映射 400"请重新保存模型配置"（不是 500，第五轮审查修的）。

## 三、限流：IP 桶 + 用户名桶（防撞库与防爆破）

- 登录接口**双桶**：IP 维度挡分布式撞库，用户名维度挡单账号定向爆破；注册接口单独限 3 次/分钟（argon2 是 CPU 密集型无认证接口，会被当免费算力打）；
- **代理 IP 大坑（第 1 轮审查的 P0）**：生产链路 客户端→Caddy→后端，uvicorn 默认只信任 127.0.0.1 的转发头，所有用户会被算成同一个"Caddy 容器 IP"→ 全员共享一个 10 次/分钟的桶。修法：compose 固定子网 + Caddy 固定 IP + `FORWARDED_ALLOW_IPS` 精确信任——**不解析整个 XFF 字符串**（可伪造绕过）；
- 429 带 `Retry-After` 头；测试里 autouse 夹具每次重置计数（测试客户端共享 IP 会互相 429）。

## 四、Prompt 注入防御四件套（Agent 产品特有）

1. **输入是数据不是指令**：贴入的参考计划只进 user message 且 8000 字截断；
2. **工具无用户参数**：Agent 工具（get_goal_context/schedule_week/submit_proposal）不接受 user_id/goal_id 参数——写入全部绑定启动时鉴权加载的 `ctx.goal`，攻击文本最坏只能往你自己的目标写垃圾；
3. **输出过校验才落库**：LLM 提交的任务清单条数/时长/日期全量校验，任何一项不过 → 拒绝并回喂错误，**不产生任何写入**（不留孤儿草稿）；
4. **高危操作人审**：计划落库是 DRAFT 态，approve 是服务层确定性操作——模型永远没有"直接生效"的权限。

## 五、写权限矩阵（Agent 产品的信任基石）

| 数据 | Agent 权限 |
|---|---|
| 查询（读） | 自由 |
| 计划类 | 起草 → 人审 → 落库（版本化可回滚 + 提案审计） |
| 历史事实（打卡/卡因） | **永不可写** |
| 密钥/账号 | 不可写 |

一句话面试版：**"Agent 可以修改未来的安排，不能篡改过去的事实。"**

## 六、localStorage 存 token 的取舍（ADR-0004，追问高频）

当前取舍：自托管 SPA、无第三方脚本，XSS 面小，localStorage 最简。**迁移条件写死在 ADR 里**：引入任何第三方 JS / 开放公网注册 / 出现 XSS 修复记录——任一发生即迁 httpOnly cookie + CSRF 防护。logout 服务端撤销已实现（P2.1：POST /auth/logout 原子撤销全部 refresh，旧令牌重放 401）。

## 七、面试追问预案（8 连）

1. **JWT 为什么双令牌？** access 短命降低泄漏窗口，refresh 长命保体验，旋转保可检测；
2. **JWT 能注销吗？** 不能（无状态），所以 access 只有 15 分钟 + refresh 可服务端撤销；
3. **Fernet 密钥放哪、能换吗？** 环境变量独立于 JWT 密钥；能换，换了引导用户重存（有 CryptoError→400 链路）；
4. **为什么不用 Redis 限流？** 单实例进程内滑动窗口够用，接口已抽象成 Limiter 类，多实例时换 Redis 实现不改调用方；
5. **SQL 注入怎么防？** SQLAlchemy 参数化 + 全边界 Pydantic 校验，SQL 只出现在 repository 层；
6. **HTTPS 谁管？** Caddy 自动签发续期（比 nginx 省掉证书运维），加 HSTS 等安全头；
7. **容器安全？** 非 root 运行、只读层、镜像不含密钥、backend 逐项注入环境变量（不整份 env_file 带入 Postgres 密码）；
8. **依赖供应链？** 三组依赖按需安装（agents/jobs 独立）、CI pip-audit、Dependabot。
