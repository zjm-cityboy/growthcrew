# ADR-0001：手机优先 PWA，而非原生 App

日期：2026-09-23 · 状态：已采纳

## 背景

产品核心场景在手机（晨推、打卡、图书馆使用），但团队（solo）若先做原生 App，需引入新工具链、承担商店审核与软著成本，且远离求职主线（Agent 工程）。

## 决策

MVP 采用 **PWA（Next.js 移动优先响应式）**，桌面端承载周审批与知识管理等重操作；微信通道（PushPlus/企微 webhook/Bark）承担可靠推送。

## 理由

1. 技术栈零新增（沿用 Next.js），迭代速度 = 刷新页面；
2. 面试演示扫码即开，无需安装 APK；
3. 调研结论：PWA 短板（无系统小组件、国内推送受限）均有缓解手段（manifest shortcuts / pinned shortcut / 微信通道）。

## 后果与迁移路径

业务逻辑 100% 在后端（API-first），未来迁移 Expo 原生 App 只需重写 UI 壳（约 1-2 周），迁移同时解锁桌面小组件与锁屏打卡（PWA 做不到的留存杠杆）。触发迁移的条件：用户主动要小组件 / 推送触达率拖累留存 / 需要商店分发。

## 被否方案

- React Native / Expo 直接起步：+2~3 周，偏离主线；
- uni-app / 小程序：React 知识不可复用（Vue 体系）。
